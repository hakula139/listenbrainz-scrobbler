# Cut a listenbrainz-scrobbler release

Read `RELEASING.md` at the repo root and execute its procedure step by step, since it is the source of truth for releases. These steps are the easiest to skip:

- [Curate the section](../../../RELEASING.md#curate-the-section) before opening the release PR.
- [Tag](../../../RELEASING.md#tag) only after separate approval.
- [Verify publication](../../../RELEASING.md#verify-publication) once the Release workflow finishes.
- Report the URLs of the release PR, the GitHub Release, and the PyPI project.
